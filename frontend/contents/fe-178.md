CSS `position` 속성은 요소를 **문서 흐름(normal flow) 안에서 어떻게 배치할지**를 정하며, `top`, `right`, `bottom`, `left`와 함께 사용합니다. 값은 다섯 가지입니다.

### static
**기본값**입니다. 문서 흐름에 따라 배치되며, `top`, `left` 같은 속성과 `z-index`가 적용되지 않습니다.

### relative
문서 흐름에서 **원래 자리를 그대로 차지한 채**, 원래 위치를 기준으로 이동합니다. 이동해도 주변 요소는 원래 자리가 비어 있지 않은 것처럼 배치됩니다. 직접 이동시키기보다는 **`absolute` 자식의 기준점**으로 많이 사용합니다.

### absolute
문서 흐름에서 **제거되어** 공간을 차지하지 않습니다. `position`이 `static`이 아닌 **가장 가까운 조상 요소**를 기준으로 배치되며, 그런 조상이 없으면 초기 컨테이닝 블록(문서)을 기준으로 합니다. 배지, 닫기 버튼, 드롭다운처럼 부모 위에 겹쳐 놓을 요소에 사용합니다.

### fixed
문서 흐름에서 제거되고, **뷰포트를 기준으로** 배치되어 스크롤해도 같은 위치에 고정됩니다. 상단 헤더, 플로팅 버튼 등에 사용합니다.

### sticky
평소에는 `relative`처럼 흐름에 따라 있다가, 스크롤되어 **지정한 임계값(`top: 0` 등)에 닿으면 `fixed`처럼 고정**됩니다. 단, 고정되는 범위는 **부모 요소의 영역 안으로 제한**되어, 부모가 화면 밖으로 사라지면 함께 사라집니다. 표의 헤더나 섹션 제목 고정에 사용합니다.

```css
.card { position: relative; }
.card .badge { position: absolute; top: 8px; right: 8px; }  /* card의 오른쪽 위 */
.table th { position: sticky; top: 0; }                       /* 스크롤 시 헤더 고정 */
```

## position: sticky가 동작하지 않는 이유는 무엇일까요? 🤔

자주 겪는 원인은 다음과 같습니다.

- **임계값을 지정하지 않았습니다.** `top`, `bottom` 중 하나가 있어야 언제 고정할지 알 수 있습니다.
- **조상 요소에 `overflow: hidden`, `auto`, `scroll`이 있습니다.** sticky는 가장 가까운 스크롤 컨테이너를 기준으로 동작하므로, 의도하지 않은 조상이 스크롤 컨테이너가 되면 그 안에서만 고정을 시도합니다.
- **부모 요소의 높이가 sticky 요소와 같습니다.** 부모 영역 안에서만 움직일 수 있으므로 이동할 공간이 없으면 고정되지 않은 것처럼 보입니다. flex 컨테이너의 자식은 기본값(`align-items: stretch`) 때문에 부모 높이만큼 늘어나 이런 문제가 생기기 쉽습니다.

## position: fixed가 뷰포트가 아닌 부모를 기준으로 배치되는 경우가 있나요? 🧐

있습니다. 조상 요소에 **`transform`, `filter`, `perspective`, `contain: paint`, `will-change: transform`** 등이 적용되면, 그 조상이 새로운 컨테이닝 블록이 되어 `fixed` 요소가 **뷰포트가 아니라 그 조상을 기준으로** 배치됩니다. 애니메이션 라이브러리가 부모에 `transform`을 걸어 두어 모달이 엉뚱한 위치에 뜨는 경우가 대표적입니다. 이럴 때는 Portal로 `body` 아래에 렌더링하거나 `<dialog>`를 사용해 해결합니다.
