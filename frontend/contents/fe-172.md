**합성 컴포넌트(Compound Component) 패턴** 은 하나의 기능을 이루는 여러 컴포넌트가 **암묵적으로 상태를 공유하면서 함께 동작**하도록 만드는 패턴입니다. HTML의 `<select>`와 `<option>`이 함께 동작하는 것과 비슷합니다.

props로 모든 것을 설정하는 컴포넌트는 요구 사항이 늘어날수록 props가 끝없이 늘어납니다.

```jsx
// ❌ 설정이 늘어날수록 props가 비대해진다
<Select
  options={options}
  showIcon
  iconPosition="left"
  renderOption={...}
  headerText="과일 선택"
/>
```

합성 컴포넌트 패턴에서는 부모가 Context로 상태를 제공하고, 자식 컴포넌트들이 그 상태를 사용합니다. 사용하는 쪽은 **필요한 조각을 원하는 순서와 구조로 조합**합니다.

```jsx
const SelectContext = createContext(null);

function Select({ value, onChange, children }) {
  const [open, setOpen] = useState(false);
  return (
    <SelectContext.Provider value={{ value, onChange, open, setOpen }}>
      <div className="select">{children}</div>
    </SelectContext.Provider>
  );
}

function Option({ value, children }) {
  const ctx = useContext(SelectContext);
  return (
    <li role="option" aria-selected={ctx.value === value} onClick={() => ctx.onChange(value)}>
      {children}
    </li>
  );
}

Select.Trigger = Trigger;
Select.Options = Options;
Select.Option = Option;

// 사용하는 쪽
<Select value={fruit} onChange={setFruit}>
  <Select.Trigger>과일 선택</Select.Trigger>
  <Select.Options>
    <Select.Option value="apple">🍎 사과</Select.Option>
    <Select.Option value="banana">🍌 바나나</Select.Option>
  </Select.Options>
</Select>
```

이렇게 하면 **레이아웃과 구성은 사용하는 쪽이 결정**하고, 상태 관리와 동작은 컴포넌트 내부가 책임지므로 유연하면서도 일관된 동작을 유지할 수 있습니다.

## Headless UI란 무엇인가요? 🤔

**Headless UI** 는 **스타일(UI) 없이 동작과 접근성 로직만 제공**하는 컴포넌트나 훅을 말합니다. 드롭다운, 모달, 탭, 콤보박스 같은 컴포넌트는 키보드 탐색, 포커스 관리, ARIA 속성처럼 구현하기 어려운 동작이 많습니다. Headless UI 라이브러리는 이 부분을 책임지고, 마크업과 스타일은 개발자가 자유롭게 작성하도록 합니다.

대표적으로 **Radix UI, React Aria, Headless UI, Ark UI** 가 있으며, 테이블 로직만 제공하는 **TanStack Table** 도 Headless 방식입니다. Radix UI를 기반으로 스타일을 입힌 컴포넌트 코드를 프로젝트에 복사해 쓰는 shadcn/ui도 이 흐름에서 등장했습니다.

## 디자인 시스템을 만들 때 Headless UI를 사용하면 어떤 장점이 있나요? 🧐

- **디자인 자유도**: 스타일이 없으므로 회사의 디자인 시스템을 그대로 입힐 수 있습니다. 스타일이 정해진 라이브러리처럼 기본 스타일을 덮어쓰느라 싸울 필요가 없습니다.
- **접근성 확보**: 검증된 키보드 상호작용과 ARIA 패턴을 그대로 사용할 수 있어, 직접 구현할 때보다 접근성 품질이 높아집니다.
- **관심사 분리**: 동작 로직과 시각적 표현이 분리되어, 디자인이 바뀌어도 동작 코드를 수정할 필요가 없습니다.

다만 스타일을 모두 직접 작성해야 하므로 초기 작업량이 늘어나고, 라이브러리가 제공하는 구조와 API를 이해해야 한다는 비용이 있습니다.
