**환경 변수** 는 API 주소, 기능 플래그, 외부 서비스의 공개 키처럼 **실행 환경(로컬, 개발, 스테이징, 운영)마다 달라지는 값을 코드 밖에서 주입**하기 위해 사용합니다. 같은 코드를 환경마다 수정하지 않고 배포할 수 있고, 설정값을 한곳에서 관리할 수 있습니다.

보통 `.env` 파일에 값을 정의하고, 빌드 도구가 이를 읽어 코드에서 사용할 수 있게 합니다.

```bash
# .env.development
VITE_API_URL=http://localhost:8080

# .env.production
VITE_API_URL=https://api.example.com
```

```js
// Vite
const apiUrl = import.meta.env.VITE_API_URL;

// Next.js
const apiUrl = process.env.NEXT_PUBLIC_API_URL;
```

`.env.local`처럼 개인 설정이나 민감한 값이 들어가는 파일은 `.gitignore`에 추가하고, 필요한 변수 목록은 값 없이 `.env.example`로 공유하는 것이 일반적입니다.

## 프론트엔드의 환경 변수는 서버의 환경 변수와 무엇이 다른가요? 🤔

서버의 환경 변수는 **실행 중에 프로세스 메모리에서 읽는 값**이라 외부에 노출되지 않습니다. 하지만 브라우저에는 `process.env`가 없습니다. 그래서 프론트엔드 빌드 도구는 **빌드할 때 코드 속 환경 변수를 실제 문자열 값으로 치환**해 번들에 그대로 넣습니다.

```js
// 작성한 코드
fetch(`${import.meta.env.VITE_API_URL}/users`);
// 빌드 결과
fetch(`https://api.example.com/users`);
```

즉, 클라이언트 코드에서 사용한 환경 변수는 **누구나 볼 수 있는 공개 값**입니다. Vite가 `VITE_`, Next.js가 `NEXT_PUBLIC_` 접두사가 붙은 변수만 클라이언트 번들에 포함하는 것도, 실수로 서버 전용 비밀 값이 노출되지 않도록 하기 위해서입니다.

따라서 데이터베이스 비밀번호, 결제 시크릿 키, 외부 API의 비밀 키는 **절대 클라이언트 환경 변수에 넣으면 안 됩니다.** 이런 값이 필요한 요청은 서버(API 라우트, BFF, 서버 컴포넌트)에서 처리하고, 프론트엔드는 그 서버를 호출해야 합니다.

## 빌드 시점에 값이 고정되면 어떤 문제가 생기나요? 🧐

환경 변수가 빌드 결과에 박혀 있으므로, **같은 빌드 결과물을 다른 환경에 그대로 배포할 수 없습니다.** 개발 서버에서 검증한 빌드를 운영에 배포하려 해도, API 주소가 달라 운영용으로 다시 빌드해야 합니다. 다시 빌드하면 검증한 결과물과 배포하는 결과물이 달라질 수 있습니다.

이 문제는 **런타임 설정** 으로 해결합니다.

- 앱이 시작할 때 `/config.json` 같은 설정 파일을 불러와 사용하고, 배포 환경마다 이 파일만 다르게 둡니다.
- 서버가 HTML을 응답할 때 `window.__ENV__`처럼 설정값을 주입합니다.
- SSR 프레임워크라면 서버에서 환경 변수를 읽어 필요한 값만 클라이언트로 전달합니다.
