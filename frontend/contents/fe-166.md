**API 모킹** 은 테스트나 개발 중에 실제 서버 대신 **미리 정해 둔 가짜 응답을 돌려주도록** 만드는 것입니다. 실제 서버에 의존하면 테스트가 느려지고, 서버 상태나 네트워크에 따라 결과가 달라지며, 에러나 빈 목록 같은 특정 상황을 재현하기 어렵기 때문입니다.

API를 모킹하는 방법은 크게 세 가지 수준이 있습니다.

1. **모듈 모킹**: `vi.mock('./api')`처럼 API 함수 자체를 가짜로 바꿉니다. 간단하지만, 실제 `fetch` 호출, 요청 URL, 헤더, 응답 파싱 코드는 검증하지 못합니다.
2. **fetch/axios 모킹**: `global.fetch`를 가짜 함수로 바꿉니다. HTTP 클라이언트 라이브러리를 바꾸면 테스트도 모두 고쳐야 합니다.
3. **네트워크 수준 모킹**: 애플리케이션 코드는 그대로 두고, **나가는 네트워크 요청을 가로채** 가짜 응답을 돌려줍니다. 대표적인 도구가 **MSW(Mock Service Worker)** 입니다.

## MSW는 어떻게 동작하나요? 🤔

MSW는 **요청 핸들러**를 정의해 두면, 해당 요청을 가로채 정의한 응답을 돌려줍니다.

```js
import { http, HttpResponse } from 'msw';

export const handlers = [
  http.get('/api/users/:id', ({ params }) => {
    return HttpResponse.json({ id: params.id, name: 'kim' });
  }),
  http.post('/api/login', () => {
    return new HttpResponse(null, { status: 401 });
  }),
];
```

- **브라우저**에서는 이름처럼 **Service Worker** 를 등록해, 페이지에서 나가는 요청을 네트워크 단에서 가로챕니다. 개발자 도구의 Network 탭에서도 요청이 그대로 보입니다.
- **Node.js(테스트 환경)** 에서는 Service Worker가 없으므로, `msw/node`의 `setupServer`가 Node의 요청 모듈을 가로채는 방식으로 동작합니다.

애플리케이션 코드는 실제 서버와 통신할 때와 **완전히 같은 코드로 실행**되므로, `fetch`를 쓰든 axios를 쓰든 TanStack Query를 쓰든 상관없이 같은 핸들러를 사용할 수 있습니다. 하나의 핸들러를 **테스트, 로컬 개발, Storybook에서 함께 재사용**할 수 있다는 것도 큰 장점입니다.

## 테스트마다 다른 응답이 필요하면 어떻게 하나요? 🧐

기본 핸들러는 성공 응답으로 두고, 특정 테스트에서만 `server.use()`로 핸들러를 **덮어씁니다.**

```js
import { server } from './mocks/server';

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterEach(() => server.resetHandlers()); // 테스트 간 영향 제거
afterAll(() => server.close());

test('서버 에러 시 에러 메시지를 보여준다', async () => {
  server.use(
    http.get('/api/users/:id', () => new HttpResponse(null, { status: 500 }))
  );
  render(<UserProfile id="1" />);
  expect(await screen.findByText('잠시 후 다시 시도해주세요')).toBeInTheDocument();
});
```

`afterEach`에서 `resetHandlers()`를 호출해야 덮어쓴 핸들러가 다음 테스트에 영향을 주지 않습니다. 또한 `onUnhandledRequest: 'error'`로 설정하면, 핸들러를 정의하지 않은 요청이 실제 네트워크로 나가는 것을 막고 빠뜨린 모킹을 바로 발견할 수 있습니다.

## API 모킹의 한계는 무엇인가요?

모킹한 응답은 **실제 서버 응답과 달라질 수 있습니다.** 백엔드가 응답 형식을 바꿔도 모킹된 테스트는 계속 통과합니다. 그래서 OpenAPI 명세에서 타입과 모킹 데이터를 생성해 서버와 계약을 맞추거나, 핵심 흐름은 실제 서버와 연결한 E2E 테스트로 보완합니다.
