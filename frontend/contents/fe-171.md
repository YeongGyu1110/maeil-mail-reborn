**커스텀 훅(Custom Hook)** 은 `useState`, `useEffect` 같은 React 훅을 조합해 만든, **이름이 `use`로 시작하는 자바스크립트 함수**입니다. 여러 컴포넌트에서 반복되는 **상태를 가진 로직(stateful logic)을 재사용**하기 위해 사용합니다.

예를 들어 여러 컴포넌트에서 네트워크 연결 상태를 확인해야 한다면, 이벤트 등록과 해제 로직을 컴포넌트마다 반복하지 않고 훅으로 추출할 수 있습니다.

```jsx
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setIsOnline(true);
    const handleOffline = () => setIsOnline(false);
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  return isOnline;
}

function StatusBar() {
  const isOnline = useOnlineStatus();
  return <p>{isOnline ? '온라인' : '오프라인'}</p>;
}
```

커스텀 훅을 사용하면 컴포넌트는 **"무엇을 하는지"만 드러내고 "어떻게 하는지"는 훅 안에 숨길** 수 있어 가독성이 좋아지고, 로직을 독립적으로 테스트할 수도 있습니다.

## 같은 커스텀 훅을 두 컴포넌트에서 사용하면 상태가 공유되나요? 🤔

아닙니다. 커스텀 훅은 **상태 자체가 아니라 상태를 다루는 로직을 공유**합니다. 훅을 호출할 때마다 그 안의 `useState`, `useEffect`가 호출한 컴포넌트에 각각 따로 연결되므로, 두 컴포넌트는 **완전히 독립적인 상태**를 가집니다.

여러 컴포넌트가 같은 상태를 공유해야 한다면 상태를 공통 부모로 끌어올리거나, Context나 전역 상태 관리 라이브러리를 사용해야 합니다.

## 왜 이름을 반드시 use로 시작해야 하나요?

React와 린트 도구가 **이 함수 안에서 훅을 호출한다는 것**을 알 수 있게 하기 위해서입니다. `eslint-plugin-react-hooks`는 `use`로 시작하는 함수를 훅으로 보고, 조건문 안에서 훅을 호출하는 등의 **훅 규칙 위반을 검사**합니다. 반대로 내부에서 훅을 전혀 사용하지 않는 함수라면 `use`를 붙이지 않고 일반 함수로 만드는 것이 맞습니다.

## 커스텀 훅을 만들 때 주의할 점은 무엇인가요? 🧐

- **구체적인 목적을 이름에 드러냅니다.** `useChatRoom`, `useDebouncedValue`처럼 목적이 분명한 훅이 좋습니다. 반대로 `useMount`처럼 `useEffect`를 단순히 감싸기만 한 훅은 의존성 배열이 숨겨져 버그를 찾기 어렵게 만들 수 있습니다.
- **너무 많은 일을 하는 훅을 피합니다.** 상태, 데이터 패칭, 이벤트 처리를 한 훅에 모두 넣으면 일부만 필요한 곳에서 재사용하기 어렵습니다.
- **반환 값의 참조를 안정적으로 유지합니다.** 훅이 반환하는 함수나 객체가 매 렌더링마다 새로 만들어지면, 이를 Effect 의존성으로 쓰는 쪽에서 무한 실행이 생길 수 있습니다.
- **테스트는 `renderHook`으로** 컴포넌트 없이 훅만 따로 검증할 수 있습니다.
