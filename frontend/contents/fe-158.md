**무한 스크롤** 은 사용자가 목록의 끝에 가까워지면 **다음 데이터를 자동으로 불러와 이어 붙이는** UI 패턴입니다. 구현 방법은 크게 두 가지입니다.

### 1. scroll 이벤트 사용
`scroll` 이벤트에서 `scrollTop + clientHeight >= scrollHeight - 여유값`인지 계산합니다. 하지만 scroll 이벤트는 매우 자주 발생하고, `scrollTop`이나 `getBoundingClientRect()` 같은 값을 읽을 때마다 **강제 레이아웃(reflow)** 이 일어날 수 있어 성능이 나빠집니다. 그래서 쓰로틀링을 함께 적용해야 합니다.

### 2. IntersectionObserver 사용
`IntersectionObserver`는 **특정 요소가 뷰포트(또는 지정한 부모 요소)와 교차하는지를 비동기로 감지**하는 Web API입니다. 목록 맨 끝에 보이지 않는 **감시용 요소(sentinel)** 를 두고, 이 요소가 화면에 들어오면 다음 페이지를 요청합니다.

```jsx
function useInfiniteScroll(onIntersect) {
  const ref = useRef(null);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => { if (entry.isIntersecting) onIntersect(); },
      { rootMargin: '200px' } // 화면에 닿기 200px 전에 미리 요청
    );
    if (ref.current) observer.observe(ref.current);
    return () => observer.disconnect();
  }, [onIntersect]);

  return ref;
}

// 목록 끝에 <div ref={sentinelRef} /> 를 둔다
```

브라우저가 교차 여부를 계산해 주므로 **메인 스레드에서 매번 위치를 계산할 필요가 없고**, 쓰로틀링 없이도 효율적으로 동작합니다.

## IntersectionObserver의 주요 옵션을 설명해주세요. 🤔

- `root`: 교차 여부를 판단할 기준 요소입니다. 기본값 `null`은 브라우저 뷰포트입니다.
- `rootMargin`: `root`의 영역을 넓히거나 줄입니다. `'200px'`처럼 주면 요소가 화면에 닿기 전에 미리 감지해, 사용자가 로딩을 기다리지 않게 할 수 있습니다.
- `threshold`: 요소가 얼마나 보였을 때 콜백을 실행할지 0~1 사이 비율로 정합니다. 광고 노출 측정처럼 "50% 이상 보였을 때"를 판단할 때 사용합니다.

무한 스크롤 외에도 **이미지 지연 로딩, 스크롤 애니메이션, 노출 로그 수집** 등에 활용합니다.

## 무한 스크롤을 구현할 때 주의할 점은 무엇인가요? 🧐

- **중복 요청 방지**: 로딩 중이거나 다음 페이지가 없으면 요청하지 않도록 해야 합니다.
- **스크롤 위치 복원**: 상세 페이지에 갔다가 뒤로 돌아오면 목록이 처음부터 다시 그려져 위치를 잃기 쉽습니다. 불러온 데이터를 캐시하고 스크롤 위치를 저장해 복원해야 합니다.
- **푸터 접근과 접근성**: 콘텐츠가 계속 추가되면 푸터에 도달할 수 없고, 키보드나 스크린 리더 사용자는 현재 위치를 파악하기 어렵습니다. 필요하면 "더 보기" 버튼을 함께 제공합니다.
- **DOM 누적**: 항목이 수천 개 쌓이면 메모리와 렌더링 비용이 커집니다. 이때는 화면에 보이는 항목만 렌더링하는 **가상화(virtualization)** 를 함께 고려합니다.
