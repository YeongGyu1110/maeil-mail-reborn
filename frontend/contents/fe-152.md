`==`는 **동등 연산자(loose equality)** 로, 두 피연산자의 타입이 다르면 **암묵적으로 타입을 변환한 뒤** 값을 비교합니다. `===`는 **일치 연산자(strict equality)** 로, 타입 변환 없이 **타입과 값이 모두 같은지** 비교합니다.

```js
1 == '1';           // true  ('1'이 숫자 1로 변환됨)
1 === '1';          // false (타입이 다름)

0 == false;         // true
'' == 0;            // true
null == undefined;  // true
null === undefined; // false
[] == false;        // true  ([] -> '' -> 0, false -> 0)
```

`==`의 변환 규칙은 직관적이지 않아 예상하지 못한 결과를 만들기 쉽습니다. 그래서 대부분의 코딩 컨벤션과 ESLint의 `eqeqeq` 규칙은 **`===` 사용을 권장**합니다. 예외적으로 `value == null`은 `null`과 `undefined`를 한 번에 검사하는 관용구로 쓰이기도 합니다.

## 암묵적 타입 변환(Type Coercion)이란 무엇인가요? 🤔

개발자가 의도하지 않았는데 **자바스크립트 엔진이 연산을 위해 값의 타입을 자동으로 바꾸는 것**을 말합니다. `Number('1')`처럼 개발자가 직접 바꾸는 것은 명시적 타입 변환이라고 합니다.

대표적인 상황은 다음과 같습니다.

- **문자열 변환**: `+` 연산자에서 피연산자 중 하나가 문자열이면 나머지도 문자열이 됩니다. `1 + '2' // '12'`
- **숫자 변환**: `-`, `*`, `/`, 비교 연산자는 피연산자를 숫자로 바꿉니다. `'5' - 1 // 4`, `'10' > 9 // true`
- **불리언 변환**: `if`, `&&`, `||`, `!` 등은 값을 truthy/falsy로 평가합니다. falsy 값은 `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN` 뿐이고 나머지는 모두 truthy입니다.
- **객체 변환**: 객체는 `valueOf()`나 `toString()`을 거쳐 원시값으로 바뀐 뒤 비교됩니다. 그래서 `[] + {}`는 `'[object Object]'`가 됩니다.

## 실무에서 truthy/falsy 때문에 생기는 버그가 있을까요? 🧐

`0`이나 빈 문자열이 **정상적인 값인데 falsy로 취급되는 경우**가 대표적입니다.

```jsx
// count가 0이면 화면에 '0'이 그대로 렌더링됨
{count && <Badge count={count} />}

// 수량 0을 '값 없음'으로 처리해 기본값 1로 덮어씀
const quantity = input || 1;
```

이럴 때는 의도를 명확히 드러내는 비교를 사용합니다. 렌더링 조건은 `count > 0 &&`처럼 불리언으로 만들고, 기본값은 `null`과 `undefined`일 때만 동작하는 **null 병합 연산자 `??`** 를 사용합니다. (`const quantity = input ?? 1`)

## `===`로도 구분하지 못하는 값이 있나요?

`NaN === NaN`은 `false`이고, `+0 === -0`은 `true`입니다. 이 두 경우까지 정확히 구분하려면 `Object.is()`를 사용합니다. React도 상태와 의존성 배열을 비교할 때 `Object.is()`를 사용합니다.
