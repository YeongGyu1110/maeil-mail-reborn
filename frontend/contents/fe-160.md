**제네릭(Generic)** 은 타입을 미리 고정하지 않고 **사용하는 시점에 타입을 매개변수처럼 전달받아 결정**하는 기능입니다. 함수가 값을 인자로 받듯이, 제네릭은 **타입을 인자로 받는다**고 이해할 수 있습니다.

```ts
// any를 쓰면 반환 타입 정보가 사라진다
function firstAny(arr: any[]): any {
  return arr[0];
}

// 제네릭을 쓰면 입력 타입이 반환 타입까지 이어진다
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]);      // number | undefined
const s = first(['a', 'b']);     // string | undefined
```

`any`를 사용하면 여러 타입을 받을 수는 있지만 타입 검사가 사라집니다. 제네릭은 **여러 타입에서 재사용할 수 있으면서도 타입 안정성을 유지**한다는 점이 핵심입니다. 대부분은 인자로부터 `T`를 **추론**하므로 `first<number>(...)`처럼 직접 적지 않아도 됩니다.

## 제네릭 제약 조건(extends)은 언제 사용하나요? 🤔

`T`가 아무 타입이나 될 수 있으면 `T`의 프로퍼티에 접근할 수 없습니다. 이때 `extends`로 **`T`가 최소한 가져야 할 형태를 제한**합니다.

```ts
function getLength<T extends { length: number }>(value: T) {
  return value.length; // length가 있다는 것이 보장됨
}

getLength('hello');   // OK
getLength([1, 2]);    // OK
getLength(10);        // Error: number에는 length가 없음
```

`keyof`와 함께 쓰면 객체에 실제로 존재하는 키만 받도록 만들 수 있습니다.

```ts
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: 'kim', age: 20 };
getProp(user, 'name');  // string
getProp(user, 'email'); // Error
```

## 프론트엔드에서 제네릭을 활용한 예시를 들어주세요. 🧐

- **API 응답 타입**: 공통 응답 형식을 정의하고 데이터 부분만 바꿔 끼웁니다.
  ```ts
  type ApiResponse<T> = { data: T; message: string };
  async function request<T>(url: string): Promise<ApiResponse<T>> {
    const res = await fetch(url);
    return res.json();
  }
  const { data } = await request<User[]>('/api/users'); // data: User[]
  ```
- **재사용 컴포넌트**: 어떤 항목 타입이든 받는 목록이나 셀렉트 컴포넌트를 만들 때, `items`의 타입이 `renderItem`, `onSelect`의 인자 타입으로 이어지게 합니다.
  ```tsx
  type ListProps<T> = { items: T[]; renderItem: (item: T) => React.ReactNode };
  function List<T>({ items, renderItem }: ListProps<T>) {
    return <ul>{items.map(renderItem)}</ul>;
  }
  ```
- **커스텀 훅과 라이브러리**: `useState<T>`, TanStack Query의 `useQuery`도 제네릭으로 데이터 타입을 전달받습니다.

참고로 `.tsx` 파일에서 화살표 함수에 제네릭을 쓸 때는 JSX 태그와 구분하기 위해 `<T,>`처럼 쉼표를 붙이거나 `<T extends unknown>`으로 작성합니다.
