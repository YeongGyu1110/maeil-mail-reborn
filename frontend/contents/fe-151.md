**얕은 복사(Shallow Copy)** 는 객체의 1단계 프로퍼티만 새로 복사하고, 그 안에 중첩된 객체는 **참조(주소)를 그대로 공유**하는 복사 방식입니다. 반면 **깊은 복사(Deep Copy)** 는 중첩된 객체까지 모두 재귀적으로 새로 만들어, 원본과 복사본이 **어떤 메모리도 공유하지 않도록** 복사하는 방식입니다.

자바스크립트에서 원시 타입(number, string, boolean 등)은 값 자체가 복사되지만, 객체와 배열은 변수에 참조가 저장됩니다. 그래서 `const b = a`처럼 대입하면 복사가 아니라 같은 객체를 가리키는 변수가 하나 더 생길 뿐입니다.

```js
const user = { name: 'kim', address: { city: 'Seoul' } };

const shallow = { ...user };
shallow.name = 'lee';            // 원본에 영향 없음
shallow.address.city = 'Busan';  // 원본의 address도 바뀜!

console.log(user.address.city);  // 'Busan'
```

스프레드 문법(`{ ...obj }`, `[...arr]`), `Object.assign()`, `Array.prototype.slice()`, `Array.from()`은 모두 **얕은 복사**입니다.

## 자바스크립트에서 깊은 복사는 어떻게 하나요? 🤔

대표적으로 세 가지 방법이 있습니다.

1. **`structuredClone()`**: 브라우저와 Node.js(17 이상)에 내장된 깊은 복사 함수입니다. `Date`, `Map`, `Set`, `RegExp`, `ArrayBuffer` 등을 지원하고 **순환 참조**도 처리합니다. 다만 함수나 DOM 노드는 복사할 수 없어 `DataCloneError`가 발생하고, 클래스 인스턴스는 프로토타입이 사라져 일반 객체가 됩니다.
2. **`JSON.parse(JSON.stringify(obj))`**: 간단하지만 `undefined`와 함수는 사라지고, `Date`는 문자열로 바뀌며, `Map`/`Set`은 빈 객체가 되고, 순환 참조가 있으면 에러가 발생합니다.
3. **라이브러리 사용**: lodash의 `cloneDeep`처럼 다양한 타입을 지원하는 함수를 사용합니다.

요즘은 특별한 이유가 없다면 내장 함수인 `structuredClone()`을 먼저 고려합니다.

## 프론트엔드에서 얕은 복사와 깊은 복사가 왜 중요한가요? 🧐

React나 전역 상태 관리 라이브러리는 **이전 상태와 다음 상태의 참조를 비교(`Object.is`)** 해서 변경 여부를 판단합니다. 그래서 중첩 객체를 직접 수정하면 참조가 그대로라 리렌더링이 일어나지 않거나, 반대로 이전 상태까지 함께 바뀌는 버그가 생깁니다.

```js
// ❌ 기존 객체를 직접 수정 -> 참조가 같아 변경을 감지하지 못함
user.address.city = 'Busan';
setUser(user);

// ✅ 바뀌는 경로만 새 객체로 만든다
setUser({ ...user, address: { ...user.address, city: 'Busan' } });
```

모든 상태를 매번 깊은 복사하면 비용이 크고, 바뀌지 않은 부분의 참조까지 달라져 `React.memo` 같은 최적화가 무력해집니다. 따라서 **바뀐 경로만 얕은 복사로 새로 만드는 방식**이 일반적이며, 중첩이 깊다면 Immer처럼 불변 업데이트를 도와주는 라이브러리를 사용합니다.
