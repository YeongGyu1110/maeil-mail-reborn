**HTTP 상태 코드** 는 서버가 요청을 어떻게 처리했는지 알려주는 **세 자리 숫자**입니다. 첫 번째 자리로 다섯 가지 범주를 나눕니다.

| 범주 | 의미 |
|---|---|
| 1xx | 정보: 요청을 받았고 처리를 계속 진행 중 |
| 2xx | 성공: 요청을 정상적으로 처리함 |
| 3xx | 리다이렉션: 요청을 완료하려면 추가 동작이 필요함 |
| 4xx | 클라이언트 에러: 요청 자체에 문제가 있음 |
| 5xx | 서버 에러: 요청은 올바르지만 서버가 처리하지 못함 |

### 자주 사용하는 상태 코드
- **200 OK**: 요청 성공
- **201 Created**: 리소스 생성 성공. 보통 `Location` 헤더에 생성된 리소스의 위치를 담습니다.
- **204 No Content**: 성공했지만 응답 본문이 없음. 삭제나 수정 API에서 자주 사용합니다.
- **301 Moved Permanently / 308 Permanent Redirect**: 리소스가 영구적으로 이동함
- **302 Found / 307 Temporary Redirect**: 리소스가 일시적으로 이동함
- **304 Not Modified**: 캐시된 리소스가 변경되지 않았으니 캐시를 그대로 사용하라는 의미
- **400 Bad Request**: 요청 형식이 잘못됨
- **401 Unauthorized**: 인증이 필요하거나 인증 정보가 유효하지 않음
- **403 Forbidden**: 인증은 되었지만 권한이 없음
- **404 Not Found**: 리소스를 찾을 수 없음
- **409 Conflict**: 현재 리소스 상태와 충돌함 (예: 이미 존재하는 아이디로 가입)
- **422 Unprocessable Content**: 형식은 맞지만 내용의 유효성 검사를 통과하지 못함
- **429 Too Many Requests**: 요청 횟수 제한 초과
- **500 Internal Server Error**: 서버 내부 오류
- **502 Bad Gateway / 504 Gateway Timeout**: 게이트웨이나 프록시가 뒤쪽 서버에서 잘못된 응답을 받았거나 응답을 제때 받지 못함
- **503 Service Unavailable**: 서버 과부하나 점검으로 일시적으로 처리할 수 없음

## 401과 403은 어떻게 다르며, 프론트엔드에서는 각각 어떻게 처리하나요? 🤔

**401** 은 "당신이 누구인지 모른다"는 뜻입니다. 로그인하지 않았거나 토큰이 만료된 경우입니다. 이름은 Unauthorized지만 실제 의미는 **인증(Authentication) 실패**입니다. 프론트엔드에서는 토큰 재발급을 시도하고, 실패하면 로그인 페이지로 이동시킵니다.

**403** 은 "누구인지는 알지만 이 작업은 허용되지 않는다"는 뜻으로 **인가(Authorization) 실패**입니다. 다시 로그인해도 해결되지 않으므로 로그인 페이지로 보내지 않고, 권한이 없다는 안내를 보여줍니다.

## 301, 302와 307, 308은 어떤 차이가 있나요? 🧐

301과 302는 명세상 원래 요청의 메서드를 유지해야 했지만, 많은 브라우저가 **POST 요청을 리다이렉트할 때 GET으로 바꿔** 보내는 방식으로 구현했습니다. 이 모호함을 없애기 위해 **메서드와 본문을 반드시 유지하는 307(일시)과 308(영구)** 이 추가되었습니다.

영구(301, 308) 리다이렉트는 브라우저와 검색 엔진이 새 주소를 기억하고 캐시하므로, 도메인 이전처럼 정말로 주소가 바뀌었을 때만 사용해야 합니다. 일시적인 이동에 영구 리다이렉트를 쓰면 되돌리기 어렵습니다.

## fetch는 4xx, 5xx 응답이 와도 에러를 던지지 않나요?

네. `fetch`가 반환한 Promise는 **네트워크 오류가 났을 때만 reject**되고, 서버가 404나 500을 응답해도 정상적으로 resolve됩니다. 그래서 `response.ok`(상태 코드가 200~299인지)를 직접 확인해야 합니다. axios는 기본적으로 2xx가 아닌 응답을 에러로 처리합니다.

```js
const res = await fetch('/api/users');
if (!res.ok) throw new Error(`요청 실패: ${res.status}`);
```
