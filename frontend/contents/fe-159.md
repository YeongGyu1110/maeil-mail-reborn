**가상화(Virtualization, Windowing)** 는 긴 목록을 렌더링할 때 **현재 화면에 보이는 항목과 그 주변 일부만 실제 DOM으로 그리고, 나머지는 그리지 않는 기법**입니다.

항목이 1만 개인 목록을 그대로 렌더링하면 DOM 노드가 수만 개 생기고, 초기 렌더링과 스타일 계산, 레이아웃 비용이 커져 스크롤이 버벅이고 메모리 사용량도 늘어납니다. 하지만 사용자가 한 번에 보는 항목은 수십 개에 불과합니다. 가상화는 이 점을 이용해 **렌더링되는 DOM 개수를 화면 크기 수준으로 일정하게 유지**합니다.

## 가상화는 어떻게 동작하나요? 🤔

1. 스크롤 컨테이너 안에 **전체 목록 높이만큼의 빈 공간**을 만들어 스크롤바가 실제 목록처럼 보이게 합니다. (예: 항목 50px × 10,000개 = 500,000px)
2. 현재 `scrollTop`과 컨테이너 높이로 **보여야 할 항목의 시작과 끝 인덱스**를 계산합니다.
3. 해당 범위의 항목만 렌더링하고, `transform: translateY()`나 `top`으로 원래 위치에 배치합니다.
4. 빠르게 스크롤할 때 빈 화면이 보이지 않도록 위아래로 몇 개를 더 그리는데, 이를 **overscan** 이라고 합니다.

직접 구현할 수도 있지만 보통 **TanStack Virtual**, **react-window**, **react-virtuoso** 같은 라이브러리를 사용합니다.

```jsx
import { useVirtualizer } from '@tanstack/react-virtual';

function List({ items }) {
  const parentRef = useRef(null);
  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: 600, overflow: 'auto' }}>
      <div style={{ height: virtualizer.getTotalSize(), position: 'relative' }}>
        {virtualizer.getVirtualItems().map((row) => (
          <div
            key={row.key}
            style={{ position: 'absolute', top: 0, width: '100%', transform: `translateY(${row.start}px)` }}
          >
            {items[row.index].name}
          </div>
        ))}
      </div>
    </div>
  );
}
```

## 항목마다 높이가 다르면 어떻게 하나요? 🧐

높이가 고정이면 위치를 바로 계산할 수 있지만, 높이가 다르면 **먼저 예상 높이로 배치한 뒤 실제로 렌더링된 항목의 높이를 측정해 보정**합니다. TanStack Virtual은 `measureElement`로 실제 높이를 측정해 반영합니다. 이 과정에서 스크롤 위치가 튀는 현상이 생길 수 있으므로 예상 높이를 실제와 비슷하게 잡는 것이 좋습니다.

## 가상화의 단점은 없나요?

- 화면 밖 항목이 DOM에 없으므로 **브라우저의 페이지 내 검색(Ctrl+F)** 으로 찾을 수 없습니다.
- 스크린 리더가 전체 목록의 개수나 구조를 알기 어려워, `aria-setsize`, `aria-posinset` 같은 속성을 보완해야 합니다.
- 검색 엔진이 전체 콘텐츠를 수집해야 하는 페이지에는 적합하지 않습니다.
- 구현이 복잡해지므로, 항목이 수백 개 수준이라면 페이지네이션이나 CSS `content-visibility: auto`처럼 더 단순한 방법으로 충분한지 먼저 검토하는 것이 좋습니다.
