**Portal** 은 컴포넌트의 자식을 **부모 컴포넌트의 DOM 계층 밖에 있는 다른 DOM 노드에 렌더링**하는 기능입니다. `react-dom`의 `createPortal(children, domNode)`으로 사용합니다.

```jsx
import { createPortal } from 'react-dom';

function Modal({ children, onClose }) {
  return createPortal(
    <div className="backdrop" onClick={onClose}>
      <div role="dialog" aria-modal="true" onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body
  );
}
```

React 트리에서는 `Modal`이 원래 위치에 그대로 있지만, 실제 DOM은 `document.body` 바로 아래에 만들어집니다.

## Portal은 왜 필요한가요? 🤔

모달, 툴팁, 드롭다운, 토스트처럼 **화면 위에 떠야 하는 UI** 를 부모 요소 안에 렌더링하면 CSS 때문에 문제가 생기기 쉽습니다.

- 부모에 `overflow: hidden`이 있으면 툴팁이나 드롭다운이 **잘려서** 보입니다.
- 부모가 `z-index`, `transform`, `opacity` 등으로 **새로운 쌓임 맥락(stacking context)** 을 만들면, 자식의 `z-index`를 아무리 높여도 부모 맥락 밖의 요소보다 위로 올라갈 수 없습니다.
- 부모에 `transform`이 있으면 자식의 `position: fixed`가 뷰포트가 아니라 **그 부모를 기준으로** 배치됩니다.

Portal로 `body` 근처에 렌더링하면 이런 부모의 CSS 제약에서 벗어날 수 있습니다. 그러면서도 컴포넌트 코드는 그 UI를 사용하는 곳 가까이에 두고, props와 상태를 그대로 전달할 수 있습니다.

## Portal 안에서 발생한 이벤트는 어디로 전파되나요? 🧐

DOM 위치와 상관없이 **React 트리를 따라 전파**됩니다. 즉 Portal 안에서 발생한 클릭 이벤트는 DOM상 부모인 `body`가 아니라, React 트리상 부모 컴포넌트의 `onClick`까지 버블링됩니다. Context도 React 트리를 따라 그대로 전달됩니다.

```jsx
<div onClick={() => console.log('부모가 클릭을 받음')}>
  <Modal>버튼</Modal> {/* 모달 안을 클릭해도 위 핸들러가 실행됨 */}
</div>
```

이 동작은 컴포넌트를 조합하기 편하게 해 주지만, 모달 내부 클릭이 의도치 않게 부모의 클릭 핸들러를 실행하는 버그를 만들 수도 있으므로 필요하면 `stopPropagation()`으로 막아야 합니다.

## Portal로 모달을 만들 때 고려할 점은 무엇인가요?

- **접근성**: 모달이 열리면 포커스를 모달 안으로 옮기고, Tab 키 포커스가 모달 밖으로 나가지 않게 가둬야(focus trap) 합니다. 닫힐 때는 모달을 연 요소로 포커스를 되돌리고, Esc 키로 닫을 수 있어야 합니다. 배경 콘텐츠에는 `inert` 속성을 주어 상호작용을 막을 수 있습니다.
- **SSR 환경**: 서버에는 `document`가 없으므로, 컴포넌트가 마운트된 이후에 Portal을 렌더링해야 합니다.
- **네이티브 `<dialog>` 요소**: `showModal()`로 연 `<dialog>`는 브라우저의 **최상위 레이어(top layer)** 에 표시되어 `z-index` 문제가 없고, 포커스 관리와 Esc 닫기, 배경 비활성화를 브라우저가 기본으로 처리합니다. 요즘은 Portal 대신 `<dialog>`를 사용하는 선택지도 많이 고려합니다.
