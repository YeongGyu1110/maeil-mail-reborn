React 19는 2024년 12월에 정식 출시된 메이저 버전으로, **폼 제출과 데이터 변경(mutation)처럼 비동기 작업을 다루는 방식**을 크게 개선했습니다. 주요 변화는 다음과 같습니다.

### Actions
**비동기 함수를 transition 안에서 실행하는 것**을 Action이라고 합니다. React 18의 `startTransition`은 동기 함수만 받았지만, React 19부터는 비동기 함수도 받을 수 있어 **대기 상태(pending), 에러, 낙관적 업데이트를 React가 함께 관리**합니다. `<form>`의 `action` 속성에 함수를 넘길 수도 있으며, 제출이 성공하면 비제어 폼 필드가 자동으로 초기화됩니다.

### useActionState
Action의 **결과 상태와 대기 여부를 함께 관리**하는 훅입니다. 이전에는 `isPending`, `error` 같은 상태를 직접 만들어야 했던 부분을 줄여 줍니다.

```jsx
function ChangeName() {
  const [error, submitAction, isPending] = useActionState(
    async (prevState, formData) => {
      const error = await updateName(formData.get('name'));
      if (error) return error;
      redirect('/profile');
      return null;
    },
    null
  );

  return (
    <form action={submitAction}>
      <input name="name" />
      <button disabled={isPending}>변경</button>
      {error && <p>{error}</p>}
    </form>
  );
}
```

### useFormStatus
`react-dom`에서 제공하는 훅으로, **부모 `<form>`의 제출 상태를 props 전달 없이** 읽을 수 있습니다. 디자인 시스템의 제출 버튼 컴포넌트를 만들 때 유용합니다.

### useOptimistic
서버 응답을 기다리는 동안 **결과를 미리 화면에 보여 주는 낙관적 업데이트**를 쉽게 구현하는 훅입니다. Action이 끝나면 낙관적 상태는 자동으로 실제 상태로 돌아갑니다.

### use
렌더링 중에 **Promise나 Context의 값을 읽는 API**입니다. Promise를 넘기면 resolve될 때까지 가까운 Suspense로 일시 중단됩니다. 일반 훅과 달리 **조건문이나 반복문 안에서도 호출할 수 있습니다.**

### 그 밖의 개선
- **`ref`를 props로 전달**: 함수 컴포넌트가 `ref`를 일반 props로 받을 수 있어 `forwardRef`가 필요 없어집니다.
- **`<Context>`를 Provider로 사용**: `<ThemeContext.Provider>` 대신 `<ThemeContext>`로 쓸 수 있습니다.
- **문서 메타데이터 지원**: 컴포넌트 안에서 `<title>`, `<meta>`, `<link>`를 렌더링하면 React가 `<head>`로 옮겨 줍니다.
- **ref 클린업 함수**: ref 콜백에서 함수를 반환하면 요소가 제거될 때 클린업으로 실행됩니다.
- **Server Components와 Server Actions의 안정화**

## useOptimistic은 언제 사용하나요? 🤔

좋아요 버튼이나 채팅 메시지 전송처럼 **성공 가능성이 높고, 즉각적인 반응이 사용자 경험에 중요한 동작**에 사용합니다.

```jsx
function Messages({ messages, sendMessage }) {
  const [optimisticMessages, addOptimistic] = useOptimistic(
    messages,
    (state, newMessage) => [...state, { text: newMessage, sending: true }]
  );

  async function formAction(formData) {
    addOptimistic(formData.get('message'));
    await sendMessage(formData);
  }

  return (
    <>
      {optimisticMessages.map((m, i) => (
        <p key={i}>{m.text}{m.sending && ' (전송 중)'}</p>
      ))}
      <form action={formAction}><input name="message" /></form>
    </>
  );
}
```

요청이 실패하면 Action이 끝날 때 낙관적 상태가 사라지고 원래 `messages`로 돌아가므로, 직접 롤백 로직을 작성하지 않아도 됩니다. 다만 사용자에게 실패 사실을 알리는 에러 처리는 별도로 해야 합니다.

## use와 useContext는 어떤 차이가 있나요? 🧐

둘 다 Context 값을 읽을 수 있지만, `useContext`는 훅 규칙에 따라 **컴포넌트 최상위에서만** 호출할 수 있습니다. `use`는 **조건문 안에서도 호출할 수 있어**, 필요한 경우에만 Context를 읽도록 작성할 수 있습니다. 또한 `use`는 Promise도 읽을 수 있습니다. 다만 클라이언트 컴포넌트 안에서 매 렌더링마다 새로 만든 Promise를 넘기면 계속 일시 중단되므로, 서버 컴포넌트에서 만든 Promise를 전달하거나 캐시된 Promise를 사용해야 합니다.
